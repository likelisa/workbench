# 统一工作台交付说明

主要入口为执行工作台、项目管理、12周计划；设置与备份在工具菜单。

新事项使用 `item`，时间安排使用 `placement`。页面和助手均调用 `ai_call` 的事务操作，助手新增、删除及推断变更继续使用确认草稿。新事项不要求父级；安排到周/日不复制身份，拆分才创建子事项。`cycleGoal` 保留本轮目标，`projectVersion` 管理项目版本。

首次启动执行 `init_unified`：迁移前生成 `before-items-*.db`，迁移旧本轮待办、周任务、日任务和项目规划为独立事项，保留旧ID映射及原表。迁移在事务中核对事项数量、外键和实际时间总量，失败回滚，重复启动不重复导入。历史分类保留，不依标题合并。原表用于兼容与恢复，新页面使用统一模型。

计划不再自动产生实际时间；已有实际记录完整保留。自动生成过实际记录的旧计划标记已回填，避免再次回填。新实际记录保存主要归属快照，任务调整不会覆盖历史。新统计取 `statistics.unified`，包含生活全量分布（含工作、未记录）、工作归属和去重事项状态。过去周期默认浏览，进入编辑后才可更正。

验收：`npm test`、`npm run build`、`cargo test --lib --manifest-path src-tauri/Cargo.toml`；界面以1440×960及900×640窗口检查。真实个人数据库在应用首次启动时迁移，开发验证只使用内存或临时测试库。
